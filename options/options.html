连不通？（指纹浏览器 / 海外代理环境必读，比特浏览器实测有效）

症状：点「保存并测试」报 ✗ 网络请求失败（Failed to fetch），括号诊断显示 「权限已授予——是网络不通」。

原因：插件的请求走浏览器网络（跟随浏览器代理）。指纹浏览器 / VPN 常配海外代理， 海外出口访问国内模型端点经常不通——不是 Key 或插件的问题。

解法（分流：模型域名直连，其余照走代理）：把模型站域名加入指纹浏览器的 代理黑名单（=「不代理的地址」）。比特浏览器：系统设置 → 全局设置 → 代理IP黑名单 → 输入 *模型域名（如 *xiaomimimo.com，星号匹配全部子域名）→ 添加 → 保存 → 关掉已打开的窗口重开（代理参数在窗口启动时注入）。其他指纹浏览器找同类的 「不代理的地址 / bypass list」设置，效果相同。

验证：在浏览器窗口的地址栏直接打开接口地址能访问 → 回这里再点「保存并测试」。

说明：黑名单只让模型域名直连本地网络，x.com 等其余流量照走代理， 指纹与出口 IP 完全不受影响。

人设提示词

定义「你是谁」：语气、身份、领域、表达习惯。生成时作为 system 提示词，单选一个为当前使用。

生成提示词

定义「怎么写」。占位符：{tweet_text} 推文内容、{author} 作者、{topic} 主题。 未放置占位符时会自动把推文/主题附在提示词末尾。

生成参数

仅 Grok 4.5 / 4.6 等推理模型支持（不发送时服务端默认 high，且推理无法关闭—— 不想思考请直接选 non-reasoning 模型）。设为 low 可显著加快生成、减少超时。 Grok 订阅授权通道若不认该参数报错，请切回「默认」。

配置备份（导出 / 导入）

升级换新版、换电脑、给朋友的浏览器配同款时：先在旧版本导出一份，装好新版后导入即恢复全部配置 （供应商与 Key、模型列表、提示词预设、生成参数、Grok 授权）。

⚠ 导出文件包含 API Key 与授权令牌（明文 JSON），只自己保存、别公开转发； 导入会整体覆盖当前配置。

所有配置仅保存在本地（chrome.storage.local），API Key 不上传任何第三方服务器。设置页的网络请求（授权/测试/更新检查）由本页直达服务商，生成由扩展后台直达——全程无中间层。
